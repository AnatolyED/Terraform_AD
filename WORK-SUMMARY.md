# Выполненная работа

- Реализовал управление OU, пользователями, группами и членством AD из YAML.
- Настроил GitLab CI/CD с отдельными state и блокировками, сохранённым планом и подтверждаемым `apply`.
- Настроил LDAP-вход по группам AD и ротацию статических учёток на пяти Vault.
- Обновил Terraform до 1.17.1 и провайдер Vault до 5.13.0. Vault Server на стенде использовал 2.2.1.

## Проверки

- Прошли шесть mock-тестов Terraform.
- Windows AD DS в VM и пять одноузловых Vault в Docker прошли сквозной тест. Git push инициировал pipeline. Два прогона прошли по 14 заданий, а повторный план после ротации показал `No changes` для AD и каждого Vault.
- Для каждого Vault подтвердил LDAP-вход, LDAPS-вход с ротированным паролем и отдельный GitLab state. Проверенные читатели из чужих групп получили `403`.

## Дефект и варианты решения

На официальных `isometry/ad` 0.5.0 и 0.6.0 делегированная учётка воспроизвела сбой защищённой OU. AD записал запрет удаления, а провайдер вернул `protected=false` после чтения без явного флага DACL. Патч на базе 0.6.0 добавил чтение DACL. Три этапа прошли с патчем. План миграции показал четыре обновления OU на месте и ноль удалений.

Предлагаю временно использовать версионированную внутреннюю сборку с проверкой lock-файла или перейти на официальный релиз после принятия исправления. Для фактической защиты OU в обоих случаях нужно ограничить `Delete Child` на родителе и `Delete Tree` на предках для учётки Terraform.
